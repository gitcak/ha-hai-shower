# Hai Shower v0.1.14

## Fixes

- **Status sensor no longer sticks on "running"** ([#1](https://github.com/gitcak/ha-hai-shower/issues/1)) -
  `Shower Status` treated the last-completed session's duration/volume as a
  live signal. Since those fields are set once a shower ends and never
  cleared, status could latch on `running` forever after the very first
  shower. It now only treats live temperature/flow readings as "running".
- **Reconfigure crashes when correcting the BLE address** - clicking
  "Reconfigure" on the integration in Settings > Devices & Services could
  crash with `AttributeError: 'NoneType' object has no attribute 'get'`
  instead of showing the address-correction form. Live-confirmed against a
  real Home Assistant instance. The reconfigure flow now reads the existing
  entry the way Home Assistant core actually invokes this step.
- **Stuck BLE notify subscriptions after a missed shower-end event** - if the
  device's shower-end notification was ever missed, the integration kept a
  temperature/shower-end subscription open indefinitely, holding the BLE
  connection and draining battery. The integration now detects two
  consecutive idle-looking polls while a subscription is still active,
  infers the missed shower-end, and cleans up automatically.
- **Silent Bluetooth proxy disconnects could hang the integration** - BLE
  reads/writes/notify calls have no built-in timeout on the BlueZ/D-Bus
  backend, so a proxy connection that drops silently could hang forever and
  block all further shower updates until Home Assistant restarted. Every BLE
  operation now has a 10-second timeout and recovers through the existing
  reconnect path instead of hanging.
- **"Shower Last seen" could report unavailable after a restart** even
  though the shower had been seen recently - the last-contact timestamp is
  now persisted alongside the other usage data and restored on startup.

## Operational Notes

- No Home Assistant config-entry migration is required.
- Restart Home Assistant after HACS updates the integration.

## Known Limitations

- Firmware version remains unavailable through ESPHome Bluetooth proxy
  security limits.
- App-side alert-setting changes are not yet read back into Home Assistant.
