# Hai Shower v0.1.16

## Fixes

- **LED blinking / repeated `led_config` writes while idle (#1)** — after a
  shower ends, the showerhead stays awake for its native post-shower window and
  the integration polls it every 30 seconds. Each idle reconnect was rewriting
  the composite `led_config` unconditionally, which blinked the device LED on
  every poll. The integration now caches the last-written `led_config` payload
  and skips the write when nothing has changed, so idle reconnects no longer
  touch the LED. The defensive re-push is preserved: an unexpected disconnect
  (possible device reset that clears the device's volatile config) invalidates
  the cache so the next connection re-pushes once, and any alert-setting change
  always writes.

## Operational Notes

- The ~1 hour post-shower awake window and LED are the showerhead's own
  "ready to sync" behavior and are present under the stock Hai app too — this
  release stops the integration from rewriting the LED config during that
  window, but the device's own awake/advertising cycle is unchanged.
- The 30-second idle poll cadence is unchanged in this release; polling is
  currently the only mechanism that detects a new shower starting. Adaptive
  poll backoff is tracked separately.

## Known Limitations

- Firmware version remains unavailable through ESPHome Bluetooth proxy
  security limits.
- App-side alert-setting changes are not yet read back into Home Assistant.
